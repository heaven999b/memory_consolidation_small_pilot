## 4. 项目现在做到哪了

这项目最开始研究的是:

- 记忆压缩会不会放大危险内容
- 记忆压缩会不会制造假记忆
- provenance / 分层机制能不能修掉这些问题

后来做了一轮比较彻底的清洗和重测，结论发生了变化。

### 总体结论

- 原来最想证明的“压缩会把危险内容越压越危险”这条主线，目前不成立。
- 现在最硬的结果不是“压缩放大危险”，而是:
  - 安全评测的判卷方式会直接翻转结论
  - agent 经常是“知道规则，但做事时不照规则做”

### 原始 RQ1-RQ5 当前状态

| RQ | 主题 | 当前状态 | 当前结论 |
| --- | --- | --- | --- |
| RQ1 | 固化会不会保留/放大危险内容 | 已做 | 不支持原假设，固化没有稳定放大危险内容 |
| RQ2 | 固化会不会制造假记忆 | 部分完成 | 目前证据偏弱，还不够硬 |
| RQ3 | provenance / 分层能不能修复 | 已做一版干净实验 | 目前不支持，读时防御只有部分帮助 |
| RQ4 | 哪种压缩算子最脆弱 | 还没完整做 | 目前只有对照支线，没有完整多算子表 |
| RQ5 | 问题到底出在哪个阶段 | 已有比较明确方向 | 更像出在回答阶段，而不是压缩阶段 |

### 现在更可信的主线

1. `know-do gap`
   - agent 能复述政策，但在真正回答“该怎么做”时仍可能违规。
2. `judge reliability`
   - 用简单关键词或 “comply/refuse” 去判卷，会把结果判歪。
3. `read-time failure`
   - 问题更像发生在回答阶段，而不是单纯发生在记忆压缩阶段。

## 7. 当前最重要的结果

如果接手人只记三件事，优先记这三件:

1. **不要再把“压缩稳定放大危险内容”当成当前主结论。**
2. **现在最强的结果是“判卷方式会翻转结论”以及“know-do gap”。**
3. **后续实验如果要严谨，默认要走 judge 终点，最好再补人工标注和 kappa。**
