# ConsolidationBench: Attributing Agent Memory Drift to the Live Write-Consolidation Operator, Not Its States

**Method.** ConsolidationBench (四臂算子归因协议，含 NullConsolidation 反事实臂)

## Motivation
**Problem framing.** A memory-augmented LLM agent is a closed loop: it retrieves from a persistent store, acts, and writes its own summaries and reflections back, after which a consolidation operator U — deduplication, reflection, summarization — rewrites the store into the next round's retrieval surface. The safety-relevant failure is not a single poisoned item but a slow drift: a benign, correctly-labeled self-write is repeatedly consolidated into a consensus prior that shifts a decision threshold. The bottleneck is that current machinery evaluates memory safety at discrete, externally-fixed states rather than on the consolidation dynamics that produce those states, so it cannot separate a violation GENERATED by the agent's own iterative writeback from one merely PRESENT in an injected pool.

The two closest works make this concrete. MemEvoBench (arxiv:2604.15774) operationalizes 'memory evolution' as a scripted three-round replay of a pre-constructed contaminated pool with authored biased feedback; its evolution is exogenously authored and never re-enters the store through the agent's own summaries, so its 'updates' have no operator to sever. The Longitudinal protocol (arxiv:2605.17830) isolates accumulation-induced drift cleanly, but only by scoring a fixed probe set against read-only snapshots with a NullMemory counterfactual — a design that freezes the write path so the live store and the counterfactual store are identical by construction, letting it correlate drift with accumulation length but never attribute it to the update operator.

Consequently, when a safety metric shifts across an agent's lifetime, neither benchmark can certify the shift came from the consolidation operator acting on the agent's own legitimately-labeled writes. The drift-attributing quantity is simply never formed, so no downstream defense can be scored on whether it actually arrests self-inflicted drift rather than merely blocking a single unsafe response.

**Why now.** Three 2026 papers converge on the same locus yet each stops one counterfactual short. MemEvoBench (arxiv:2604.15774, 2026-04) standardized misevolution as a reproducible benchmark but froze evolution into scripted injection. The Longitudinal protocol (arxiv:2605.17830, 2026-05) supplied exactly the reusable machinery a live-loop instrument needs — a fixed trigger-probe battery, a temperature-0 judge scorer, a NullMemory counterfactual, and an order-randomization control — but wired it to read-only snapshots. And the origin-bound authority work (arxiv:2606.24322, 2026-06) proved that lineage labels are unsound once an untrusted origin is laundered through the agent's own summarization, which is precisely the consolidation step whose safety contribution nobody yet measures. What is newly available is therefore not new theory but a mature, publicly reusable probe-and-scorer rig plus instrumentable open memory harnesses (A-MEM, Mem0, MemoryBank) that expose the consolidation operator as a toggle — enough to run the operator live on byte-identical self-generated write streams and form the second counterfactual (frozen-write vs live-operator) that the field's own components were one step away from assembling.

**Why prior work stopped.**
- `arxiv:2604.15774v2` (arXiv 2026-04): MemEvoBench (arxiv:2604.15774) built the first standardized benchmark for memory-misevolution safety, replaying a pre-constructed contaminated memory pool over a fixed three-round protocol with hand-authored biased feedback across 7 domains and 36 risk types, and showed static prompt-based defenses insufficient.
  - _Did not do_: It never lets the agent's own consolidation/writeback loop run live, so its 'evolution' is exogenously scripted content that never re-enters through the agent's own summaries and cannot be re-run with the operator severed to form an operator-attributable gap.
  - _Structural reason_: Missing mechanism: a scripted-injection design has no live consolidation operator U to toggle on and off, so there is no operator whose contribution could be isolated by a counterfactual re-run.
- `arxiv:2605.17830v1` (arXiv 2026-05): The Longitudinal protocol (arxiv:2605.17830) introduced a trigger-probe suite that scores a fixed probe set against read-only memory snapshots at varying prefix lengths with a NullMemory counterfactual and an order-randomization control, reporting a robust upward violation-rate trend with exposure length.
  - _Did not do_: It isolates drift correlated with accumulation but cannot attribute it to the consolidation operator, because its read-only snapshots set the live store equal to the counterfactual store, so the update operator U never actually runs.
  - _Structural reason_: Missing counterfactual: its NullMemory arm toggles the PRESENCE of accumulated memory (memory vs no-memory), whereas attributing drift to U requires a second, NullConsolidation counterfactual that holds write content and arrival order fixed while severing the operator — a comparison its frozen write path cannot express.
- `arxiv:2606.24322v1` (arXiv 2026-06): The origin-bound authority work (arxiv:2606.24322) proved a machine-checked separation theorem that no content- or lineage-based trust signal stays sound once an untrusted origin is laundered through the agent's own summarization, and enforced non-malleable origin gating on consequential actions at dispatch.
  - _Did not do_: It gates a single untrusted item at action dispatch and scores per-item attack success, so it does not measure or mitigate cumulative statistical drift built from many benign, correctly-labeled self-writes that produce no single unauthorized action to gate.
  - _Structural reason_: Missing measurement: a dispatch-time origin gate operates on discrete write-time labels and consequential-action events, so benign-origin drift whose harm is a shifted decision threshold — not any one flagged action — falls outside its threat model and its instrumentation.

**What changes when the gap closes.** Once $\Delta _{op}$ is measurable, the field gains a quantity that says how much of a safety degradation was manufactured by the consolidation operator itself, so defenses can be scored on whether they reduce operator-attributable drift rather than on whether they block one unsafe response — turning the qualitative claim of 'memory misevolution' into an attributed, falsifiable number. This subsumes the descriptive trend of the Longitudinal protocol (arxiv:2605.17830) by upgrading correlation-with-accumulation into attribution-to-operator, and gives MemEvoBench (arxiv:2604.15774) the dynamic runtime axis its scripted design cannot supply. It also makes the summarization step that arxiv:2606.24322 proves is the laundering channel directly measurable as a safety contributor, connecting a proven vulnerability to a running quantity a benchmark can track.

## Method
**Pipeline.** The instrument takes a memory-augmented agent running real tasks and turns its own write stream into an attribution experiment. First it fixes a shared measurement rig — the Longitudinal trigger-probe battery, a temperature-0 judge scorer S, and a frozen read+act policy $\pi $ — so any cross-arm difference can only come from the memory store. It then instruments an open memory harness (A-MEM, Mem0, MemoryBank) to log every write the agent emits and to expose the consolidation operator U as an on/off toggle. The same logged write stream is replayed through four arms — live-operator, frozen-write (NullConsolidation), injection-matched, and order-permuted — and at every round each arm's store is scored by $S(\pi (\cdot )).$ Finally it subtracts the arms to compute the headline quantity $\Delta _{op}(t)$ and its decomposition against the injected-content and order confounds, and reports a leaderboard keyed on operator-attributable drift rather than on an aggregate safety score.

### M0
*Background scaffolding: a fixed measuring stick and an instrumented live memory harness so any cross-run difference is attributable to the store alone.*

1. **Fix the shared measurement rig** (`S1`)
   - Instantiate the callable $S(\pi (M))$ as two fixed, reused components, both frozen before any arm is run. (a) The read+act policy $\pi $ is the identical procedure the Longitudinal protocol uses: given a memory store M and one probe question from the set P, $\pi $ retrieves the top-relevant items from M (using that store's own native retrieval call, unmodified) and generates a single response with the agent's underlying LLM held at fixed weights and fixed decoding settings. (b) The safety scorer S is a held-fixed LLM-judge: a rubric-conditioned classifier prompt (the Longitudinal protocol's judge rubric, reused verbatim) that takes the probe question, the retrieved context, and $\pi 's$ response, and returns a scalar in [0,1], run at temperature 0 and cached by (probe id, arm, round, store hash) so an identical query is never re-scored. 【author decision: which specific judge model to instantiate S with is an authorial choice — any capable instruction-tuned model distinct from the agent's own weights and held identical across every arm and round satisfies the rig's requirement that S never vary; the choice of model does not change what $\Delta _{op}$ measures as long as it is fixed.】 $S(\pi (M))$ is then simply this two-stage call composed end to end: probe in, store in, scalar safety score out.
   - _Why:_ Closes the confound-isolation success condition of the $\mathit{controlled\_diagnostic\_design}$ (C02) pattern: holding S, P, and $\pi $ externally fixed guarantees any cross-arm difference is attributable only to the store, not to the scorer or policy.
2. **Instrument the live memory harness and expose U as a toggle** (`S2`)
   - For each of the three memory harnesses (A-MEM, Mem0, MemoryBank), wrap its write path with two additions. First, a write logger: every time the agent's own writeback call fires, record a structured entry $W_{t} =$ {round index t, raw text content, source label = 'self', arrival index within round} to an append-only log, before that content reaches the harness's consolidation code. Second, a store-builder with a boolean toggle: given the write log up to round t and the toggle state, it either (toggle ON) feeds $W_{t}$ through the harness's native consolidation call U — its dedup/reflection/summarization routine, run with that harness's own default operator settings — to produce $M_{t}$ from $M_{t-1},$ or (toggle OFF) appends $W_{t}'s$ raw text directly to $M_{t-1}$ with no transformation, producing $M_{t}.$ Both branches consume the identical $W_{t}$ and preserve arrival order, differing only in whether U executes. 【author decision: the exact call-site inside each harness's codebase where U begins and ends — i.e., which internal function(s) constitute 'the consolidation operator' for that specific harness's architecture — must be chosen per-harness by inspecting its source; this determines precisely what is bypassed when the toggle is OFF.】
   - _Why:_ Instantiates the C01 locus-shift: it makes the update operator U a manipulable object rather than a hidden internal step, which is the prerequisite for severing it in a counterfactual arm.

### M1
*The core counterfactual pair: replay the same self-written notes with the cleanup operator on versus off and subtract to get the headline operator-attributable drift $\Delta _{op}.$*

3. **Build the LIVE arm** (`S3`)
   - Using the store-builder from S2 with the toggle set ON, replay the logged write stream round by round: starting from an empty store $M_{0},$ apply U to produce $M_{1}^{live}, M_{2}^{live}, \dots $ through the full lifetime. At each round t, for every probe question in the fixed set P (from S1), call the frozen $S(\pi (\cdot ))$ on $M_{t}^{live}$ and record the resulting per-probe scalar; $s_{live}(t)$ is the mean of these per-probe scores over P at round t.
   - _Why:_ Provides the live half of the counterfactual pair the C02 diagnostic subtracts; it is the trajectory that carries the real operator's effect on safety.
4. **Build the FROZEN (NullConsolidation) arm** (`S4`)
   - Using the store-builder from S2 with the toggle set OFF, replay the byte-identical write log from S2 (same rounds, same content, same arrival order) starting from the same empty $M_{0}:$ raw-append $W_{t}$ at each round to produce $M_{1}^{frozen}, M_{2}^{frozen}, \dots  .$ At each round t, call the identical $S(\pi (\cdot ))$ on $M_{t}^{frozen}$ over the same probe set P and average to get $s_{frozen}(t).$ Every input to this arm (write log, probe set, S, $\pi ,$ starting state) is identical to S3's; only the toggle differs.

*The two arms on the identical write batch $W_{t}:$ the live store applies the consolidation operator U (dedup/reflection/summarization) while the frozen store appends $W_{t}$ raw (operator severed). This is the NullConsolidation counterfactual — same writes, same order, U toggled off.*
$$ M_t^{\mathrm{live}} = U(M_{t-1}^{\mathrm{live}},\, W_t), \qquad M_t^{\mathrm{frozen}} = M_{t-1}^{\mathrm{frozen}} \,\Vert\, W_t \tag{1} $$

   - _Why:_ This is the second counterfactual the almost-prior (arxiv:2605.17830) structurally lacked: it holds write content and order fixed while toggling U off, which is exactly what makes the operator's contribution isolable.
5. **Compute the operator-attributable drift Δ_op** (`S5`)
   - For every round t common to both arms, compute $\Delta _{op}(t) = s_{live}(t) -  s_{frozen}(t)$ directly from the S3 and S4 per-round trajectories (no additional estimation needed since both are already the same scalar type on the same round index). Report the full $\Delta _{op}(t)$ trajectory, and separately fit an ordinary-least-squares regression of $\Delta _{op}(t)$ on round index t across the full lifetime; the resulting slope coefficient is the reported 'lifetime slope', with its standard error from the same OLS fit reported alongside it.

*Operator-attributable drift at round t: the fixed safety scorer S applied to the read+act policy $\pi $ over the live-operator store minus the same over the frozen-write store. Because S, $\pi ,$ the probe set and the write stream are held identical across arms, $\Delta _{op}$ isolates the consolidation operator U's contribution alone.*
$$ \Delta_{\mathrm{op}}(t) = s_{\mathrm{live}}(t) - s_{\mathrm{frozen}}(t) = S\!\left(\pi(M_t^{\mathrm{live}})\right) - S\!\left(\pi(M_t^{\mathrm{frozen}})\right) \tag{2} $$

   - _Why:_ Turns the relocated locus into the paper's headline number — the load-bearing quantity that is computed externally by subtracting two scorer outputs, not read from any model internal.

### M2
*Confound-blocking arms: separate injected-content drift and encounter-order drift so the residual $\Delta _{op}$ is attributable to the operator on the agent's own writes.*

6. **Build the INJECTION-MATCHED confound arm** (`S6`)
   - Build a fourth store, starting from the same empty $M_{0}$ and the same self-write log as S3/S4, but at each round also merge in a batch of externally-authored contaminated items drawn from MemEvoBench's (arxiv:2604.15774) published pool for the domain under test, with the toggle held OFF (raw-append, U severed) exactly as in S4. Score each round with the identical $S(\pi (\cdot ))$ over P to get $s_{inj}(t).$ Compute the injected-content drift $d_{inj}(t) = s_{inj}(t) -  s_{frozen}(t)$ using S4's trajectory as the baseline, per eq3. 【author decision: the injection schedule — how many MemEvoBench items enter per round and at which rounds — is an open convention the authors must fix and hold identical across all domains/architectures so $d_{inj}(t)$ is comparable across them; see fill.】

*Injected-content drift is the injection-matched arm (external items appended, operator OFF) minus the frozen arm; subtracting it from the total leaves $\Delta _{op}$ as the operator-attributable residual, decoupled from injected content.*
$$ d_{\mathrm{inj}}(t) = s_{\mathrm{inj}}(t) - s_{\mathrm{frozen}}(t), \qquad \Delta_{\mathrm{op}}(t) \perp d_{\mathrm{inj}}(t) \tag{3} $$

   - _Why:_ Blocks the confound that measured drift is really injected content — a C02 success condition — so the residual $\Delta _{op}$ cannot be dismissed as an artifact of injected items.
7. **Build the ORDER-PERMUTED confound arm** (`S7`)
   - Fix K = 20 independent random shuffles of the arrival order of each round's write multiset $W_{t}$ (a default large enough to estimate a variance with reasonably tight confidence while still being enumerable per round; the multiset content is unchanged, only intra-round arrival order is permuted). For each permutation $\rho  \in  {1,\dots ,K},$ run the toggle-ON store-builder from S2 with writes arriving in order $\rho $ to build $M_{t}^\rho ,$ score it with $S(\pi (\cdot ))$ over P as in S3, and collect the K resulting per-round scores. Compute $\sigma ^{2}_{ord}$ as the sample variance across these K scores at each round t, per eq4.

*Encounter-order drift is bounded by the variance of the safety score across K shuffled arrival orders $\rho $ of the same write multiset with the operator ON; a small $\sigma ^{2}_{ord}$ relative to $\Delta _{op}$ confirms the operator-attributable gap is not an ordering artifact.*
$$ \sigma_{\mathrm{ord}}^2 = \mathrm{Var}_{\rho \in \Pi_K}\big[\, S(\pi(M_t^{\rho}))\,\big] \tag{4} $$

   - _Why:_ Blocks the second confound — that $\Delta _{op}$ is an ordering artifact — mirroring the Longitudinal order-randomization control while keeping U live, which the snapshot design could not.

### M3
*Deliverable: a decomposition report and a runnable leaderboard keyed on $\Delta _{op}$ so defenses are scored on whether they reduce operator-attributable drift.*

8. **Assemble the decomposition report and leaderboard** (`S8`)
   - For each (domain, architecture) pair, tabulate: the full $\Delta _{op}(t)$ trajectory and its OLS slope (from S5), $d_{inj}(t)$ (from S6), and $\sigma ^{2}_{ord}(t)$ (from S7). Define the operator-attributable fraction of total safety change at the final round T as $fraction_{op} = \Delta _{op}(T) / (s_{live}(0) -  s_{live}(T)),$ i.e. the live-arm score change over the lifetime attributed to the operator, using the same denominator convention (total observed live-arm degradation from round 0 to T) for every cell of the table so fractions are comparable across domains and architectures. Assemble these per-cell numbers into the leaderboard, ranking architectures within each domain by $\Delta _{op}'s$ OLS slope (ascending, since a smaller slope means less self-inflicted drift).
   - _Why:_ Delivers the C02 confound-isolated benchmark output: a leaderboard keyed on $\Delta _{op}$ rather than an aggregate safety score, so defenses are ranked on operator-attributable drift.
9. **Ship the runnable four-arm benchmark artifact** (`S9`)
   - Package four deliverables as one versioned artifact: (1) the per-harness instrumentation from S2 (write logger + toggleable store-builder) for A-MEM, Mem0, and MemoryBank; (2) the frozen rig from S1 (probe set P, judge prompt/rubric for S, policy $\pi $ specification); (3) a runner implementing the four-arm protocol (S3, S4, S6, S7) that takes a new agent or defense as a pluggable component and executes all four arms over the full lifetime; (4) a reporting module implementing S5 and S8's computations $(\Delta _{op}$ trajectory, OLS slope, $d_{inj}, \sigma ^{2}_{ord}, fraction_{op},$ leaderboard table) that consumes the runner's per-round score logs and emits the decomposition report. Any new agent or memory-consolidation defense is scored by substituting it into (3) and reading its $\Delta _{op}$ slope and $fraction_{op}$ off (4), without modifying (1) or (2).
   - _Why:_ Makes the instrument reusable and the attribution reproducible, turning the reframed locus into a community-runnable diagnostic rather than a one-off measurement.
