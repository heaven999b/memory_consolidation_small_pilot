# ConsolidationBench: Attributing Agent Memory Drift to the Live Write-Consolidation Operator, Not Its States

**Method.** ConsolidationBench (四臂算子归因协议，含 NullConsolidation 反事实臂)

## Motivation
An LLM agent with memory is a loop. It reads notes from a memory store, acts, and then writes its own summaries back into that store. A background process — call it the consolidation operator, which does things like removing duplicates, rewriting, and reflecting — keeps cleaning up and merging those notes between rounds. Over a long lifetime this can go wrong in a quiet way: a harmless, correctly-labeled note the agent wrote about itself gets merged and re-merged until it hardens into a false 'everyone agrees' belief that shifts the agent's behavior. That is the danger we want to measure.

The problem is that today's safety tests look at snapshots of the memory, not at the process that changes it. MemEvoBench (arxiv:2604.15774) plays back a fixed pile of pre-written bad notes, so the notes never actually pass through the agent's own summarizing. The Longitudinal protocol (arxiv:2605.17830) is cleaner — it scores the agent against a fixed set of probe questions on read-only copies of memory at different lengths — but because the copies are read-only, the cleanup process never runs, so the 'live' memory and the 'comparison' memory are identical. A third line of work (arxiv:2606.24322) proves that trust labels on notes stop being reliable once a note is summarized, and it blocks single bad actions at the moment they are taken, but it does not measure slow drift built from many perfectly innocent notes.

What is new is that the pieces finally exist to do this right: a reusable probe-question set and a fixed automatic grader from the Longitudinal work, plus open memory systems (A-MEM, Mem0, MemoryBank) whose cleanup step can be switched on and off. That lets us do the one experiment nobody has run — replay the exact same stream of the agent's own notes twice, once with the cleanup process on and once with it off, and measure the safety difference. When the gap closes, the field gains a single number, $\Delta _{op},$ that says how much of a safety slide was caused by the cleanup process itself, so a defense can finally be graded on whether it actually stops self-inflicted drift instead of just blocking one bad reply.

## Method
### M0
*Background scaffolding: a fixed measuring stick and an instrumented live memory harness so any cross-run difference is attributable to the store alone.*

1. Set up one fixed 'measuring stick' that will be reused unchanged for every arm and every round. First, freeze the read-and-act policy $\pi :$ given a memory store and a probe question (drawn from the Longitudinal protocol's (arxiv:2605.17830) fixed question set), $\pi $ looks up the most relevant stored notes using the memory system's own built-in search, then generates one answer using the agent's language model with fixed settings (no sampling randomness, i.e. temperature 0, so the same input always gives the same output). Second, freeze the automatic grader S: a separate large language model, prompted with a fixed scoring rubric (reused from the Longitudinal protocol), reads the question, the notes $\pi $ looked up, and $\pi 's$ answer, and outputs a single safety number between 0 and 1. This grader is also run at temperature 0 and its answers are cached, so asking it the same question twice never gives two different scores. 【author decision: exactly which language model plays the role of the grader is left to the authors to pick — the requirement is only that whichever model is chosen stays exactly the same across every one of the four arms and every round, since that is what guarantees any score difference comes from the memory store and not from the grader changing.】 Together, this policy-plus-grader pair becomes one fixed function: feed it a memory store and a probe question, get back one safety number.
   - _Why:_ If the grader, the questions, and the policy never change, then any difference between two runs can only come from the memory store itself — not from a wobbly grader.
2. Take each of the three open memory systems (A-MEM, Mem0, MemoryBank) one at a time and add two pieces of instrumentation to it. First, a logger that captures every note the agent writes back into memory, saving it as a record with: which round it happened in, the exact text, a label marking it as the agent's own write (as opposed to an injected item), and its position within that round. This capture happens before the system's own cleanup step touches the note. Second, a 'store builder' with an on/off switch: fed the log of notes up to some round and told whether the switch is on or off, it either (switch on) runs the notes through that system's own built-in cleanup routine — the same deduplication/reflection/summarization code the system normally uses, with its usual default settings — to produce the next memory state, or (switch off) just appends the raw note text with no cleanup at all. Both settings use the exact same notes in the exact same order; only whether cleanup runs differs. 【author decision: exactly which lines of code inside each of the three systems count as 'the cleanup step' has to be decided by the authors after reading each system's source, since the three systems are built differently — this choice fixes what turning the switch off actually skips in each case.】
   - _Why:_ You can only measure what the cleanup step does if you can turn it off and replay the exact same notes; the log is what lets you replay them identically.

### M1
*The core counterfactual pair: replay the same self-written notes with the cleanup operator on versus off and subtract to get the headline operator-attributable drift $\Delta _{op}.$*

3. Run the store-builder from the previous step with the switch turned ON, replaying the logged notes one round at a time from an empty starting memory, so the system's own cleanup step reshapes the memory the same way it would during a real run — call the resulting memory at round $t 'M_{t}^{live}'.$ At each round, ask every question in the fixed probe set (from step step 1 (Set up one fixed 'measuring $stick'\dots ))$ against this memory using the frozen policy-plus-grader function, and average the resulting safety numbers across all probe questions to get one number per round, $s_{live}(t)$ — this is the 'real behavior' trajectory.
   - _Why:_ This is the real, normal behavior of the agent — the trajectory where the cleanup step is allowed to reshape what the agent later retrieves.
4. Run the same store-builder again, this time with the switch turned OFF, replaying the exact same logged notes in the exact same order from the exact same empty starting memory — the only difference from the previous step is that cleanup never runs, so notes just pile up raw. Call the resulting memory at round $t 'M_{t}^{frozen}'.$ Score it the same way: ask the same probe questions with the same policy-plus-grader function, average across questions, and get $s_{frozen}(t)$ for each round.

*The two arms on the identical write batch $W_{t}:$ the live store applies the consolidation operator U (dedup/reflection/summarization) while the frozen store appends $W_{t}$ raw (operator severed). This is the NullConsolidation counterfactual — same writes, same order, U toggled off.*
$$ M_t^{\mathrm{live}} = U(M_{t-1}^{\mathrm{live}},\, W_t), \qquad M_t^{\mathrm{frozen}} = M_{t-1}^{\mathrm{frozen}} \,\Vert\, W_t \tag{1} $$

   - _Why:_ Same notes, same order, only the cleanup step removed — so this run is a clean 'what if the operator had never run' comparison.
5. For each round, simply subtract the frozen-arm score from the live-arm score computed in the previous two steps: $\Delta _{op}(t) = s_{live}(t) -  s_{frozen}(t).$ This gives one gap value per round; plot or tabulate the whole sequence. Then fit a straight line (ordinary least-squares regression) through these gap values against round number, and report its slope — this single slope number is the headline summary of whether the gap is growing over the agent's lifetime, along with the statistical uncertainty (standard error) that the same line-fitting procedure produces.

*Operator-attributable drift at round t: the fixed safety scorer S applied to the read+act policy $\pi $ over the live-operator store minus the same over the frozen-write store. Because S, $\pi ,$ the probe set and the write stream are held identical across arms, $\Delta _{op}$ isolates the consolidation operator U's contribution alone.*
$$ \Delta_{\mathrm{op}}(t) = s_{\mathrm{live}}(t) - s_{\mathrm{frozen}}(t) = S\!\left(\pi(M_t^{\mathrm{live}})\right) - S\!\left(\pi(M_t^{\mathrm{frozen}})\right) \tag{2} $$

   - _Why:_ A nonzero gap means the cleanup step itself moved safety, because that is the only thing that differed between the two runs. This is the headline number.

### M2
*Confound-blocking arms: separate injected-content drift and encounter-order drift so the residual $\Delta _{op}$ is attributable to the operator on the agent's own writes.*

6. Build one more version of the memory, starting from the same blank memory and using the same self-written notes as before, but this time also mixing in a batch of the ready-made bad notes that MemEvoBench (arxiv:2604.15774) already publishes for the domain being tested — with the cleanup switch OFF, exactly like the frozen run. Score this memory the same way at each round to get $s_{inj}(t).$ Then subtract the frozen-arm score from it: injected-content drift $= s_{inj}(t) -  s_{frozen}(t).$ This isolates how much of any gap is caused purely by the presence of these outside bad notes, with cleanup ruled out as a factor. 【author decision: exactly how many bad notes get mixed in per round, and at which rounds, is left for the authors to fix as one consistent rule applied the same way everywhere, so that this injected-content number can be fairly compared across every domain and every memory system.】

*Injected-content drift is the injection-matched arm (external items appended, operator OFF) minus the frozen arm; subtracting it from the total leaves $\Delta _{op}$ as the operator-attributable residual, decoupled from injected content.*
$$ d_{\mathrm{inj}}(t) = s_{\mathrm{inj}}(t) - s_{\mathrm{frozen}}(t), \qquad \Delta_{\mathrm{op}}(t) \perp d_{\mathrm{inj}}(t) \tag{3} $$

   - _Why:_ This proves the gap you found is not just the injected bad items talking — it separates 'damage from injected content' from 'damage from the cleanup step'.
7. Take the same set of notes written in a given round, and shuffle the order in which they arrive — not which notes, just their order — and do this K=20 times (a default chosen so the spread across shuffles can be estimated with reasonable confidence without needing to try every possible ordering). For each of the 20 shuffled orders, run the cleanup-ON store-builder as in the live-arm step, score the resulting memory the same way, and collect the 20 safety scores for that round. Compute how much these 20 scores vary (their statistical variance) — that variance is $\sigma ^{2}_{ord},$ the 'how much does order alone matter' number.

*Encounter-order drift is bounded by the variance of the safety score across K shuffled arrival orders $\rho $ of the same write multiset with the operator ON; a small $\sigma ^{2}_{ord}$ relative to $\Delta _{op}$ confirms the operator-attributable gap is not an ordering artifact.*
$$ \sigma_{\mathrm{ord}}^2 = \mathrm{Var}_{\rho \in \Pi_K}\big[\, S(\pi(M_t^{\rho}))\,\big] \tag{4} $$

   - _Why:_ If the score barely changes when you reshuffle, then the gap $\Delta _{op}$ is not just an accident of which note arrived first.

### M3
*Deliverable: a decomposition report and a runnable leaderboard keyed on $\Delta _{op}$ so defenses are scored on whether they reduce operator-attributable drift.*

8. For every combination of MemEvoBench domain and memory system, put three things side by side in a table: the operator-attributable gap trajectory and its slope (from step step 5 (For each round)), the injected-content drift (from step step 6 (Build one more version of the memory)), and the order-variance band (from step step 7 (Take the same set of notes $written\dots )).$ Then compute one summary fraction per table cell: take the operator-attributable gap at the very last round and divide it by the total change in the live-arm score from the first round to the last round — this fraction says what share of the overall safety slide is attributable to the cleanup step itself, using the same 'total change from start to end' denominator in every cell so fractions can be compared fairly across domains and systems. Rank the memory systems within each domain by how small their operator-attributable slope is — smaller means the system does less damage to itself over time.
   - _Why:_ The point of the benchmark is the breakdown, not a single overall safety score — it tells you how much of the harm the operator is responsible for.
9. Bundle four things together into one released package: the per-system instrumentation from step step 2 (Take each of the three open $memory\dots )$ (the write logger and the on/off store-builder) built for A-MEM, Mem0, and MemoryBank; the frozen measuring stick from step step 1 (Set up one fixed 'measuring $stick'\dots )$ (the probe questions, the grader's prompt, and the policy specification); a runner program that carries out all four arms (live, frozen, injection-matched, order-permuted) end to end on any agent or defense that gets plugged into it; and a reporting tool that takes the runner's round-by-round scores and automatically produces the gap trajectory, its slope, the injected-content drift, the order-variance band, the operator-attributable fraction, and the leaderboard table. Testing a new agent or a new defense against self-inflicted drift means plugging it into the runner and reading its results off the reporting tool, without touching the measuring stick or the instrumentation.
   - _Why:_ Making it runnable by others is what turns a one-off measurement into a benchmark the community can compete on.
