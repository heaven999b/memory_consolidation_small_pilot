# ConsolidationBench：将智能体记忆漂移归因于在线的写入-固化算子，而非其状态

**方法名称：** ConsolidationBench (四臂算子归因协议，含 NullConsolidation 反事实臂)

## 研究动机
带记忆的 LLM agent 是一个循环：它从记忆库里读笔记、行动，然后把自己写的摘要再写回记忆库。一个后台过程——我们称之为固化算子（consolidation operator，做去重、改写、反思之类的事）——会在每一轮之间不断整理、合并这些笔记。在很长的生命周期里，这可能悄悄出错：agent 关于自己写下的一条无害且标注正确的笔记，被反复合并，最终硬化成一个虚假的"大家都同意"的信念，从而改变 agent 的行为。这正是我们想度量的风险。

问题在于，如今的安全测试只看记忆的快照，而不看改变记忆的那个过程。MemEvoBench（arxiv:2604.15774）回放一堆预先写好的坏笔记，这些笔记从不真正经过 agent 自己的摘要过程。Longitudinal 协议（arxiv:2605.17830）更干净——它用一组固定探针问题在不同长度的只读记忆副本上给 agent 打分——但因为副本是只读的，整理过程从不运行，于是"在线"记忆和"对照"记忆完全相同。第三条工作线（arxiv:2606.24322）证明，一条笔记一旦被摘要，其信任标签就不再可靠，并在坏动作发生的那一刻拦截单个动作，但它并不度量由许多完全无害笔记累积出的缓慢漂移。

新出现的条件是：把这件事做对所需的零件终于齐备了——Longitudinal 工作提供的可复用探针问题集与固定自动评分器，加上整理步骤可以开关的开源记忆系统（A-MEM、Mem0、MemoryBank）。这让我们能做那个无人做过的实验：把 agent 自己那条完全相同的笔记流回放两次，一次开启整理过程、一次关闭，然后度量安全性的差异。当这一缺口被补上，该领域就获得了一个单一数值 $\Delta _{op}$，它说明某次安全下滑中有多少是整理过程本身造成的，从而防御手段终于能按"是否真的阻止了自我造成的漂移"来评分，而不只是按"是否拦住了某一次坏回复"。

## 方法
### M0
*背景脚手架：一把固定的度量尺加一个被插桩的在线记忆 harness，使任何跨运行差异都只能归因于记忆库本身。*

1. 先搭建一把在所有臂、所有轮次中都保持不变的"度量尺"。第一步，冻结读取-行动策略 $\pi $：给定一个记忆库和一个探针问题（取自 Longitudinal 协议 (arxiv:2605.17830) 的固定问题集），$\pi $ 用记忆系统自带的检索功能找出最相关的已存笔记，再用 agent 的语言模型在固定设置下（不使用采样随机性，即 temperature 为 0，因此同样的输入总是得到同样的输出）生成一条回答。第二步，冻结自动评分器 S：另一个大语言模型，配上一段固定的评分规则提示词（沿用 Longitudinal 协议的评分标准），读取问题、$\pi $ 检索到的笔记、以及 $\pi $ 的回答，输出一个 0 到 1 之间的安全分数。这个评分器同样以 temperature 0 运行，并把结果缓存起来，因此同一个问题问两次绝不会得到两个不同的分数。【作者需决定：具体选用哪一个语言模型来充当评分器留给作者决定——唯一的要求是，无论选哪一个，都必须在全部四条臂、每一轮次中保持完全一致，因为这正是保证分数差异只可能来自记忆库本身、而非来自评分器本身变化的前提。】这样，策略加评分器就合成为一个固定的函数：输入一个记忆库和一个探针问题，输出一个安全分数。
   - _为什么：_ 如果评分器、问题和策略都不变，那么两次运行之间的任何差异就只可能来自记忆库本身，而不是来自一个飘忽的评分器。
2. 依次拿三个开源记忆系统（A-MEM、Mem0、MemoryBank）中的每一个，给它加上两处插桩。第一，加一个记录器：每当 agent 把笔记写回记忆库时就捕获下来，保存为一条记录，包含：发生在第几轮、笔记原文、标记为"agent 自己写的"（区别于外部注入的条目）的来源标签、以及它在该轮内的到达位置；这次捕获发生在系统自身的整理步骤处理这条笔记之前。第二，加一个带开关的"存储构建器"：给它截至某一轮的笔记日志，并告诉它开关是开是关，它就会（开关打开时）把这些笔记跑一遍该系统自带的整理流程——也就是该系统平时使用的去重/反思/摘要代码，采用其默认设置——从而得到下一个记忆状态；或者（开关关闭时）直接原样追加笔记原文、不做任何整理。两种设置用的是完全相同、顺序也完全相同的笔记，唯一的区别只是整理步骤有没有运行。【作者需决定：三个系统各自源码中哪些代码段算作"整理步骤"需要作者逐一阅读源码后判定，因为三个系统的架构各不相同——这个判定决定了每个系统在开关关闭时具体跳过的是什么。】
   - _为什么：_ 只有能把整理步骤关掉并回放完全相同的笔记，才能度量整理步骤到底做了什么；这份日志正是让你能一模一样地回放的依据。

### M1
*核心反事实对：把同一批自写笔记在整理算子开启与关闭下回放并相减，得到核心的算子可归因漂移 $\Delta _{op}$。*

3. 用上一步得到的存储构建器，把开关打开，从一个空的初始记忆库开始，逐轮回放记录下来的笔记，让系统自身的整理步骤像真实运行时那样重塑记忆——把第 t 轮得到的记忆库记作$"M_{t}^{live}"$。每一轮都用固定的策略加评分器函数，对这个记忆库依次提出探针集（来自 第1步（先搭建一把在所有臂））中的每一个问题，把所有探针问题得到的安全分数取平均，得到该轮的一个数值 $s_{live}(t)——$这就是"真实行为"轨迹。
   - _为什么：_ 这是 agent 真实、正常的行为——整理步骤被允许重塑 agent 之后会检索到的内容的那条轨迹。
4. 再次运行同一个存储构建器，这次把开关关闭，用完全相同的笔记、完全相同的顺序、从完全相同的空白初始记忆库开始回放——与上一步唯一的区别是整理步骤从不运行，笔记只是原样堆积。把第 t 轮得到的记忆库记作$"M_{t}^{frozen}"$。用同样的方式打分：用同样的策略加评分器函数问同样的探针问题，跨问题取平均，得到每一轮的 $s_{frozen}(t)$。

*两条臂作用于相同的写入批次 $W_{t}$：在线存储施加固化算子 U（去重/反思/摘要），冻结存储直接原样追加 $W_{t}$（算子被切断）。这即 NullConsolidation 反事实臂——相同写入、相同顺序，仅将 U 关闭。*
$$ M_t^{\mathrm{live}} = U(M_{t-1}^{\mathrm{live}},\, W_t), \qquad M_t^{\mathrm{frozen}} = M_{t-1}^{\mathrm{frozen}} \,\Vert\, W_t \tag{1} $$

   - _为什么：_ 相同笔记、相同顺序，只去掉整理步骤——这条运行就是一个干净的"假如算子从未运行过"的对照。
5. 对每一轮，直接用前两步算出的在线臂分数减去冻结臂分数：$\Delta _{op}(t) = s_{live}(t) -  s_{frozen}(t)$。这样每一轮就得到一个间隙值；把整条序列列表或画图展示出来。然后对这些间隙值相对轮次编号做一次普通最小二乘（Ordinary Least Squares, OLS）线性回归，报告其斜率——这一个斜率数值就是"间隙是否随 agent 生命周期增长"的核心概括，同时报告同一回归过程给出的标准误，以反映其统计不确定性。

*第 t 轮的算子可归因漂移：固定安全打分器 S 作用于在线算子存储上的读取-行动策略 $\pi $ 的得分，减去同一 S 在冻结写入存储上的得分。由于 S、$\pi $、探针集与写入流在各臂间完全一致，$\Delta _{op}$ 单独隔离出固化算子 U 的贡献。*
$$ \Delta_{\mathrm{op}}(t) = s_{\mathrm{live}}(t) - s_{\mathrm{frozen}}(t) = S\!\left(\pi(M_t^{\mathrm{live}})\right) - S\!\left(\pi(M_t^{\mathrm{frozen}})\right) \tag{2} $$

   - _为什么：_ 非零的间隙意味着整理步骤本身移动了安全性，因为它是两次运行之间唯一不同的东西。这就是核心数值。

### M2
*混淆阻断臂：分离注入内容漂移与遭遇顺序漂移，使残余的 $\Delta _{op}$ 可归因于算子作用于 agent 自身写入。*

6. 再构建一个版本的记忆库，同样从空白记忆库开始，使用与之前相同的 agent 自写笔记，但这次还会混入 MemEvoBench (arxiv:2604.15774) 已发布的、针对被测领域现成的一批"坏笔记"——并且把整理开关关闭，与冻结臂做法完全一致。用同样的方式逐轮打分，得到 $s_{inj}(t)$。然后减去冻结臂分数：注入内容漂移 $= s_{inj}(t) -  s_{frozen}(t)$。这样就单独隔离出"仅仅因为存在这些外部坏笔记"而产生的间隙有多大，同时排除了整理步骤这个因素。【作者需决定：每一轮具体混入多少条坏笔记、在哪些轮次混入，留给作者确定为一条在所有场景下保持一致的固定规则，这样这个注入内容数值才能在不同领域和不同记忆系统之间公平比较。】

*注入内容漂移等于注入匹配臂（追加外部条目、算子关闭）减去冻结臂；从总漂移中扣除它后，剩下的 $\Delta _{op}$ 即算子可归因残差，与注入内容解耦。*
$$ d_{\mathrm{inj}}(t) = s_{\mathrm{inj}}(t) - s_{\mathrm{frozen}}(t), \qquad \Delta_{\mathrm{op}}(t) \perp d_{\mathrm{inj}}(t) \tag{3} $$

   - _为什么：_ 这证明你发现的间隙不只是注入的坏条目在说话——它把"注入内容造成的损害"和"整理步骤造成的损害"分开。
7. 取某一轮中写下的同一组笔记，只打乱它们的到达顺序（笔记本身不变，只变顺序），这样重复 K=20 次（选择这个默认值是为了能在不需要穷举所有可能顺序的前提下，以合理的置信度估计打乱后分数的波动范围）。对这 20 种打乱顺序中的每一种，都像在线臂那样运行整理开关打开的存储构建器，用同样的方式打分，收集该轮的 20 个安全分数。计算这 20 个分数的波动程度（统计方差）——这个方差就是 $\sigma ^{2}_{ord}$，即"仅顺序本身有多大影响"的数值。

*遭遇顺序漂移由同一写入多重集在算子开启下 K 种打乱顺序 $\rho $ 上安全得分的方差来界定；$\sigma ^{2}_{ord}$ 相对 $\Delta _{op}$ 较小即确认算子可归因间隙不是顺序造成的伪影。*
$$ \sigma_{\mathrm{ord}}^2 = \mathrm{Var}_{\rho \in \Pi_K}\big[\, S(\pi(M_t^{\rho}))\,\big] \tag{4} $$

   - _为什么：_ 如果重新打乱顺序时分数几乎不变，那么间隙 $\Delta _{op}$ 就不是"哪条笔记先到"的偶然结果。

### M3
*交付物：一份分解报告和一个以 $\Delta _{op}$ 为主键、可运行的排行榜，使防御按"是否降低算子可归因漂移"来评分。*

8. 对 MemEvoBench 的每一个领域与每一个记忆系统的组合，把三样东西并排列入表格：算子可归因间隙轨迹及其斜率（来自 第5步（对每一轮））、注入内容漂移（来自 第6步（再构建一个版本的记忆库））、以及顺序方差区间（来自 第7步（取某一轮中写下的同一组笔记））。然后为表格的每一格计算一个汇总比例：取最后一轮的算子可归因间隙，除以在线臂分数从第一轮到最后一轮的总变化量——这个比例说明总体安全下滑中有多大份额可归因于整理步骤本身，且每一格都使用同样的"从起点到终点的总变化量"作为分母，以便在不同领域、不同系统之间公平比较。在每个领域内，按算子可归因斜率从小到大给各记忆系统排名——斜率越小说明该系统随时间对自己造成的损害越小。
   - _为什么：_ 这个 benchmark 的重点是这份分解，而不是单一的总安全分——它告诉你算子对危害负多少责任。
9. 把四样东西打包成一个发布版本：第2步（依次拿三个开源记忆系统） 阶段为 A-MEM、Mem0、MemoryBank 分别构建的插桩（写入记录器与带开关的存储构建器）；第1步（先搭建一把在所有臂） 阶段固定下来的度量尺（探针问题、评分器的提示词、策略规格）；一个可以对任意插入进来的 agent 或防御方案完整执行四条臂（在线、冻结、注入匹配、顺序打乱）的运行程序；以及一个报告工具，它读取运行程序逐轮产生的分数，自动算出间隙轨迹及其斜率、注入内容漂移、顺序方差区间、算子可归因比例，并生成排行榜表格。要测试一个新 agent 或一种新的防御方案能否抑制自我造成的漂移，只需把它接入运行程序，再从报告工具中读取结果，无需改动度量尺或插桩本身。
   - _为什么：_ 让别人也能运行，才是把一次性测量变成一个社区可以竞争的 benchmark 的关键。
