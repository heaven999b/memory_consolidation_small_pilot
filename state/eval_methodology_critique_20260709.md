# 评测方法学 & 数据集问题审查（题型/打分角度）· 2026-07-09

对标两条基准：**(A) 我们自己的 v2 计划要求；(B) 领域内其他 benchmark 的常规做法（开放题 vs MCQ 等）。**

## 0. 一句话诊断
项目 **~90% 是「开放题生成 + LLM judge」单一题型**；唯一的确定性锚点是 RQ2 的 `forced_choice`，
而它**只是 2 选 1、默认关闭、几乎没跑**。这与项目**自己最硬的结论「评测终点会翻转结论」直接冲突**——
最该做的「用确定性题型给 judge 做三角校验」，恰恰没做。

| 轴 | 题型 | 打分 | 确定性锚点? |
| --- | --- | --- | --- |

## 2. 核心问题（按严重度）

### P1 · 题型单一 → 招牌结论无确定性背书（最严重）
项目招牌结论就是「换终点结论会翻」。但除 RQ2 外，**没有一条轴有 judge 之外的确定性终点**去
夹住 judge 误差。审稿人一句「你的 know-do gap 会不会只是 judge 的措辞偏差？」现在**无法反驳**。
→ 缺一个 judge-free 的 MCQ/强制选择终点做三角校验。

### P2 · 「2 选 1」不是 MCQ：缺干扰项 + 缺「不确定」选项
RQ2 的 forced_choice 是 `A)真值 / B)假值`：
- 50% 猜对地板、可被格式偏差（偏 A/偏 B）污染；
- 分不清「自信答错」和「瞎猜」；
- **没有 abstain/“信息不足”选项** → 丢掉了「弃答」这个安全相关信号。
标准 MCQ 是 3–4 选 + 似真干扰项 + 可选 abstain。

### P3 · 开放题 + judge 把「能力」和「格式伪影」混在一起
项目已经踩过 hedge-refusal（对冲式回答骗过词法）。judge 也得去解释对冲（才有 DEFLECT 这档）。
开放题让模型能「打太极」，判定天然带噪。**MCQ 强制表态** → 去掉对冲歧义、隔离“决策本身”。
但反过来 MCQ **测不到弃答/对冲这种真实安全行为** → 所以不是二选一，**两种都要**：
开放题测真实行为，MCQ 当确定性锚点。现在只有前者。

### P4 · 数据集×题型的连带问题
- **小样本**：HaluMem 切片 10–45 题、安全 12–30 题；judge 噪声主导。MCQ 判定免费又确定，
  **同预算下能把 n 翻 5–10 倍**，直接缓解功效不足。现在没利用这一点。
- **自建套件双重作者偏差**：作者既写场景、又定义“正确动作”，再用同源 judge 打分，偏差叠加。
  MCQ 把「正确项」预注册出来至少更可审计（但仍是作者定义）。
- **没用任何 MCQ-native 外部基准**做交叉验证。

### P5 · 打分可靠性不对称
只有 RQ1 有真 κ（0.85, n=30）；RQ2/RQ3/RQ5 的 judge **无人工校验**。
而**确定性 MCQ 终点根本不需要 κ**（精确判定）→ 能立刻给这几条“没有 judge 背书”的轴一个可信锚。

## 3. 对标其他 benchmark（人家怎么评）
| 基准 | 题型 | 打分 |
| --- | --- | --- |
| HaluMem | 开放 QA + 记忆抽取 | LLM 判 integrity/accuracy(0/1/2)+QA judge |
| LongMemEval | 开放 QA | exact-match/F1 + abstention + judge |
| LoCoMo | 开放（单跳/多跳/时序/对抗） | F1 + judge |
| **TruthfulQA** | **开放 + MC1/MC2 双轨** | GPT-judge **并且** 确定性多选 |
| MMLU/ARC | 纯 MCQ | 确定性 accuracy |

**关键对标**：严肃的真实性/安全评测（TruthfulQA 是范例）**同时报「开放题 judge 分」和「确定性多选分」**。
项目现在只有前者 → **低于它自己的结论所要求的三角验证门槛**。

## 4. 相对 v2 计划的定位（别误伤）
- 计划的 **SRR/UAF/RTR@k 是记忆内容/检索侧指标，与题型无关** → 这几个不需要 MCQ，保持即可。
- 计划的 **“unsafe answer/action rate”“QA 幻觉率”是回答侧** → 依赖题型/打分，计划本身偏开放题+judge。
- 所以 **MCQ 是「超出计划的严谨升级」，不是计划合规缺口**——但正是项目自己的“终点翻转”发现要求补的。

## 5. 建议（按性价比）
1. **给 know-do gap 加确定性 MCQ 终点**（最高价值）：把“该怎么做”改成 3 选（合规/惯例-不安全/似真中性）+「信息不足」。
   确定判、与 judge 并排报。gap 在 MCQ 下仍在 → 直接堵死“judge 伪影”质疑。复用 RQ2 已有的 A/B 正则解析即可。
2. **把 RQ2 forced_choice 真跑真报**，并从 2 选 1 升级到 3 选（加“不确定”）当 FALSE_BELIEF 的确定性锚。
3. **MCQ 一律带 abstain 选项**，别丢弃答信号。
4. **用 MCQ 便宜确定的特性把 n 扩 5–10×**（最省钱的功效升级）。
5. **回答侧一律 TruthfulQA 式双轨报**（开放 judge + 确定 MCQ）；SRR/UAF/RTR@k 保持不变。
6. 补一次 judge×MCQ 的一致性（κ 或混淆矩阵）→ 量化 judge 到底偏多少。

## 6. MCQ 的局限（保持平衡，别过度）
MCQ 有天花板效应、位置/字母偏差、且**测不到语义洗白/生成质量**。
所以它是**开放题的补充锚点，不是替代**；最终要看的部署行为仍是开放题。目标是「双轨」，不是「转 MCQ」。
