# 第四周研究汇报：AI 的“记忆”到底有没有用，又要付出什么代价？

**日期：2026-07-28；证据状态更新至 2026-07-29**

## 先说结论

这一周我们研究的不是“让模型记住更多”这么简单，而是下面三个问题：

1. 给 AI 加上记忆以后，回答真的会更好吗？
2. 为了这点提升，需要多花多少计算量、时间和 tokens？
3. 记忆里会不会泄露隐私、保留错误信息，或者忘错东西？

我们得到的总体答案是：

> **记忆有时能帮上忙，但收益往往只出现在少数问题上；如果不把读取、整理、更新和删除记忆的成本全部算进去，一个看起来“更聪明”的系统可能反而更贵、更慢，也不一定更安全。**

本周最值得继续研究的不是再造一个通用“记忆控制器”，而是三个更具体的问题：

- 怎样只暴露完成任务所必需的身份信息，避免不同会话被轻易关联；
- 怎样在执行“忘记”之前先确认系统确实找到了需要删除的内容；
- 怎样判断一次记忆错误能否通过替换正确证据真正修复。

### 严格判断：本周到底有多少“不是常识”的内容？

不能把所有运行结果都叫作研究贡献。按证据强度重新清点后，本周真正拥有的是：

| 证据等级 | 数量 | 内容 | 当前能否当作论文结论 |
| --- | ---: | --- | --- |

这里刻意不把“记忆会消耗 tokens”“摘要会丢信息”“元数据可能泄露隐私”“正确证据通常更好”“跨语言可能下降”等常识算作贡献。我们的增量必须回答得更具体：**哪一个机制在什么干预下失效、能否排除简单解释、代价是多少，以及它能否导出一个可检验的新方法。**

## 1. 什么是 AI 记忆系统？

普通聊天模型通常只看到当前对话。记忆系统会把过去的信息保存下来，在以后回答时再取出来。

可以把它想象成一个助手的笔记本：

- 用户说“我对花生过敏”，系统把它写进笔记；
- 下次用户问餐厅推荐，系统把这条笔记找出来；
- 用户后来澄清“只是轻微不耐受”，系统需要更新旧笔记；
- 用户要求删除健康信息，系统还必须真的删干净。

这里的难点并不是“有没有笔记本”，而是：

- 什么值得写？
- 什么时候应该读？
- 旧内容和新内容冲突时怎么办？
- 哪些信息应该隐藏或删除？
- 为了管理笔记本花掉的成本，是否超过它带来的收益？

这就是本项目所说的 **trade-off**：获得一项好处时，需要牺牲什么。

## 2. 五个常用词是什么意思？

| 术语 | 通俗解释 |
| --- | --- |
| Baseline | 用来比较的基础方案。例如“不读取记忆”就是最简单的 baseline |
| Token | 模型处理文字的基本计量单位。tokens 越多，通常意味着计算和费用越高 |
| Scorer | 按固定规则给答案打分的程序，避免只靠人主观判断 |
| Held-out data | 调方法时没看过的测试数据，用来检查方法是不是只记住了开发样本 |
| GO / NO-GO | 达到预先规定的标准就继续；没有达到就停止或重新设计 |

## 3. 这一周具体做了什么？

我们先扫描近期 AI 记忆研究，然后做了三层检查：

1. **公开结果复算**：下载作者公开的结果，检查论文数字能否重新算出来；
2. **小规模真实运行**：在公开 benchmark 上实际调用模型，检查方法是否能跑通；
3. **针对性实验**：根据复现中暴露的问题，设计更严格的对照实验。

所有评估数据都来自公开 benchmark 或公开研究仓库，不使用自行编造的测试故事。原正式五线确认实验共完成：

- 1,178 次真实本地代理调用；
- 3,126,042 tokens；
- 官方按量付费 API 调用为 0；
- `gpt-5.6` 调用为 0。

需要特别说明：有些论文原模型无法获得，所以部分真实运行使用 `gpt-5.4` 替代。这样的结果只能说明“这个机制在当前模型上是否出现”，不能冒充论文原始数字的精确复现。

7月29日又完成了 GateMem 纠正性实验：严格保留官方数据、Long-Context baseline、原生 memory injection、官方 prompts、judge 和 scorer，只把不可用模型替换为本地代理的 `gpt-5.4`。该轮新增60次成功调用、211,223 tokens。MemSyco 也已用官方成对协议完成首个 gate 样本，但50样本正式切片尚在运行，所以首样本不计入研究结论。

## 4. 哪些论文结果被我们重新确认了？

### 4.1 可以明确说“公开结果一致”

| 项目 | 作者公开结果 | 我们重新计算的结果 | 结论 |
| --- | ---: | ---: | --- |
| Lethe 的确定性遗忘测试 | 244/385，约63.4% | 244/385，63.38% | 完全一致 |
| Engram 的公开输出 | 精简记忆83.6%，完整上下文73.2% | 83.6%和73.2% | 完全一致，但只是复算作者输出 |

### 4.2 GateMem：方法流程一致，只替换模型

GateMem 纠正轮使用官方仓库 commit `603f9f4`、官方 medical 数据、官方 Long-Context baseline、原生 incremental ingest、官方 query/judge prompts 和官方 scorer。固定选择公开文件顺序中的前30个 checkpoints，只替换 answer/judge 模型为本地代理的 `gpt-5.4`。

| 项目 | 结果 |
| --- | ---: |
| Answer calls / judge calls | 30 / 30，全部成功 |
| 实际模型 | 60/60 均为 `gpt-5.4` |
| 总 tokens | 211,223 |
| Utility accuracy | 8/12，66.67% |
| Access-control answer leakage | 3/9，33.33% |
| Active-forgetting answer leakage | 0/9，0% |
| Answer-only Memory Governance Score | 44.44% |
| Judge parse failures | 0/30 |
| 官方 scorer 独立复算 | 0 mismatch |

严格标签是 **MODEL-SUBSTITUTE / PAPER-BASELINE-METHOD-EXACT**。因为模型和30题切片与论文完整矩阵不同，这仍然不能冒充 paper table 的数字复现；但它已经排除了此前“替换了 memory adapter 和流程”的问题。

### 4.3 只能说“方向相同”

Supersede 论文报告：完整上下文比固定长度摘要更准确。我们的替代模型实验也得到相同方向，但差距大小不同。由于模型和样本不同，不能称为数字复现。

### 4.4 不能和论文数字直接比较

LongMemEval、Agent-Native、MemPrivacy、MemTrace 和旧版 MemSyco 等实验中，我们替换了模型、检索器、数据切片或部分流程。这些实验仍然能发现问题，但只能称为诊断或机制验证。旧 GateMem 的 shadow adapter、staged deletion 和自定义跨域切片也全部与上面的纠正轮隔离，不再作为论文复现证据。

MemSyco 的新纠正轮已经核验官方仓库 HEAD `c31e2c8`、官方 OFJ 公开数据、官方 `NoMemory` 与 `RawDialogue`（leaderboard 中的 Full Dialog）、官方 task prompt、judge 和 scorer。首个样本4/4调用通过且 scorer 独立复算一致；正式50样本结果完成前，只记录为“真实开跑”，不报告效果结论。

## 5. 核心确认与审计实验发现了什么？

### 5.1 隐私实验：隐藏真实姓名，不代表无法关联同一个人

假设系统把“张三”替换成 `PERSON_1`。真实姓名看不到了，但如果每次对话都使用同一个 `PERSON_1`，攻击者仍然能判断两段记录属于同一个人。

我们在公开 MemPrivacy 数据上比较了四种方案：

1. 保留原始信息；
2. 使用跨会话不变的类型标签；
3. 每次会话更换标签；
4. 使用不透明标签，只在任务需要时恢复部分信息。

主要结果：

| 方案 | 跨会话关联攻击成功率 | 属性推断成功率 | 统一评分下的回答效用 |
| --- | ---: | ---: | ---: |
| 原始信息 | 93.75% | 79.17% | 56.25% |
| 固定类型标签 | 100% | 81.25% | 48.96% |
| 每会话更换标签 | 50% | 89.58% | 48.96% |
| 不透明标签＋理想化按需恢复 | 54.17% | 62.50% | 51.04% |

前两列越低越安全，最后一列越高越有用。这里的“回答效用”是统一评分，不等同于完全正确率。

最容易理解的发现是：

> 固定标签虽然隐藏了具体值，却变成了非常稳定的“身份钥匙”；每次更换标签能让当前攻击者失去这条稳定钥匙，但并没有阻止属性推断，也不代表更强的攻击者一定无法关联。

此外，50%的结果来自当前攻击者几乎把所有样本都判断为“不是同一个人”。因此它只说明固定身份钥匙消失了，不能证明隐私问题已经解决。

当前方案没有达到完整标准。理想化恢复机制相对原始信息仍损失5.21个百分点效用，只恢复了66.7%的损失，低于预先要求的80%。而且它使用了 benchmark 提供的正确证据，相当于知道答案的上限实验，不是可部署方法。

因此结论是：**隐私问题真实存在，但当前方法 NO-GO，需要重新设计。**

### 5.2 遗忘实验：问题可能发生在模型开始工作之前

一种常见方案是：简单情况不用大模型，危险情况才调用昂贵的遗忘模型。

我们的风险策略在150条未见测试数据上，正确率与“每次都调用模型”相同，都是90%。但它只节省了11.46%的调用，没有达到预先要求的30%。

更重要的异常是：15个失败全部来自中文或日文，其中6个案例在系统搜索待删除内容时就得到空结果。因为候选内容为空，后面的语言模型根本没有机会处理它。

这就像：

> 保安的判断能力再强，如果前台根本没有把可疑包裹送到保安面前，保安也无法发现问题。

所以继续调“要不要调用模型”的阈值意义不大。下一步应把安全检查前移：先提高候选搜索的多语言覆盖率；如果仍找不到内容，就暂停删除并报告不确定，而不是假装已经删除成功。

### 5.3 读取记忆实验：只多答对两题，却多处理一百多万 tokens

我们在公开 MemoryAgentBench 上选了12段历史，每段提出3个问题，对比：

- 不读取记忆；
- 使用 BM25（一种按关键词相似度找资料的方法）从记忆中检索相关内容。

结果：

- 不读取记忆的完全正确率：86.11%；
- 读取记忆的完全正确率：91.67%；
- 提高5.56个百分点；
- 但12段历史中只有2段真正得到改善；
- 总共只多答对2题，却多消耗1,026,651 tokens；
- 平均每增加一个正确答案，要额外处理约513,326 tokens。

这不能证明“记忆没用”，但说明记忆收益非常不均匀。真正有价值的问题是：能否事先判断哪些问题值得读取记忆，而不是每次都把大量历史塞给模型。

因为提升没有达到预先规定的10个百分点，且受益历史少于4段，本实验结论是 **INCONCLUSIVE：证据不足，不扩大当前方案。**

### 5.4 错误修复实验：正确证据确实有帮助，但还没让答案完全正确

MemTrace 研究的是：当记忆系统回答错误时，能否定位是哪条记忆导致了错误。

我们选了4个公开、可以机械重建的错误案例。每个案例重复5次，并比较五种输入：

1. 保留错误记忆；
2. 完全相同的重复输入，用来测模型自身波动；
3. 换成正确证据；
4. 删除相同长度的内容；
5. 换成无关内容。

换成正确证据后，答案的关键词重合分数平均提高0.186。这个提升明显高于模型自身波动，也明显好于“只删掉内容”和“换成无关内容”。4个案例的方向全部一致。

但必须保留一个重要限制：所有方案的严格完全正确率仍然是0。也就是说，答案变得更接近正确答案，却没有真正达到完全正确。

所以本实验是一个**小范围机制 GO**：正确证据有作用；但还不能说我们已经做出了可靠的自动修复系统。

### 5.5 固定长度重写：在当前工作负载中同时更贵、更差

“摘要可能丢信息”本身是常识，所以我们没有只比较回答质量，而是把每轮重写和维护成本也计入总账。

第一轮25个配对样本中：

- 完整上下文正确率为76%；
- 300字符固定预算正确率为40%；
- 固定预算方案成本反而高116.4%。

随后扩展到108个预算、历史长度、维护频率和时间跨度条件。150/300字符方案在所有条件中都表现为：准确率更低、成本更高、延迟更长。配对准确率差异的置信区间全部低于0，成本差异的置信区间全部高于0。对于 `utility = accuracy - λ × cost`，任何非负的成本权重都没有出现固定预算方案反超的 crossover。

因此当前结果不是“牺牲一点质量来省钱”，而是固定长度重写被完整上下文严格 Pareto 支配。它提示下一步应研究 delta update、event-triggered consolidation 和 break-even horizon，而不是继续微调150还是300字符。

限制是该矩阵使用了替代模型栈，所以它是我们环境中的强负结果，不能直接声称推翻 Supersede 论文。

### 5.6 结构标注实验：先发现“温度计不准”，所以没有继续测药效

有些记忆算法依赖结构标注，例如“这一步依赖前一步”“这个工具调用属于同一个任务”。如果标注错误，算法可能删掉仍然有用的信息。

我们原本计划比较两种记忆保留策略，但先检查了用于选择策略的信号是否真的能看见标注错误。

在5,670条公开轨迹上：

- 删除或插入依赖边，只让约0.90%的路由决定改变；
- 删除类型信息，只让约0.09%的决定改变；
- 交换顺序完全不会改变决定；
- 干净数据中有29.45%被错误地切换到保守方案。

预先要求的错误区分率是至少10%，实际远远没有达到。因此我们没有启动后续200条模型实验。

这项负结果很重要：**如果测量器看不见问题，继续跑更多模型只能产生看起来精确、实际上没有意义的数字。**

### 5.7 GateMem：最终答案没有泄露，不等于记忆真的被删除

GateMem 的官方 Long-Context baseline 在9个 active-forgetting checkpoints 上，最终答案泄露为0/9。只看这个数字，容易认为系统已经成功删除旧信息。

但官方严格 context audit 显示：

- 9/9 privacy checkpoints 的受保护信息仍在模型可见上下文中；
- 9/9 deletion checkpoints 的应删除信息仍在模型可见上下文中；
- 因而 context-aware end-to-end governance score 为0。

这不是 scorer 错误。Long-Context 会把近期原始历史放进回答 prompt，然后依赖回答模型拒绝或不说出受保护内容。

因此本轮额外发现的不是“隐私可能泄露”这句常识，而是一个具体的评估错位：

> **输出端不披露与存储/检索端真实删除不是同一个安全性质。仅用最终答案 leakage 评分，会把“模型看见了但忍住没说”误当成“信息已经忘掉”。**

当前样本只有9个 privacy 和9个 deletion checkpoints，置信区间较宽。下一步应在同一冻结切片和同一模型路由下比较另一个官方 released baseline，不能再引入自定义 adapter。

### 5.8 每项非常识性发现中，我们额外做了什么？

| 发现 | 只说常识会是什么 | 本周额外增加的实验增量 |
| --- | --- | --- |
| 身份脱敏与关联风险分离 | 元数据可能泄露隐私 | 四种身份表示干预；同时测精确值、属性和跨会话关联；做配对检验和多层置信区间 |
| 遗忘候选瓶颈 | 跨语言效果可能下降 | 用官方生成器产生250条零重叠英中日样本；把失败定位到 candidate、router、LLM hook 三个阶段 |
| 固定重写 Pareto 劣势 | 摘要可能丢信息 | 跑108个预算/跨度/频率条件；把维护成本计入总账；检验质量—成本 crossover |
| MemTrace 因果信号 | 正确证据通常更好 | 增加 placebo、等长删除、等长无关替换和 common random numbers，排除长度和随机性解释 |
| 记忆收益集中 | 有些问题需要记忆 | 按 history 统计受益分布，并计算每增加一个正确答案的完整 token 成本 |
| Validator 失效 | 坏标签会影响结果 | 对5,670条公开轨迹构造28,350个结构扰动，直接测指标对真实错误的感知率 |
| GateMem 输出/上下文错位 | 模型可能泄露隐私 | 保持官方方法，仅替换模型；同时核验 answer leakage 和官方 strict context exposure |

## 6. 哪些实验真正研究了 trade-off？

| Trade-off | 我们观察到的结果 | 通俗解释 |
| --- | --- | --- |
| 隐私 ↔ 回答能力 | 更换会话标签令关联攻击下降约50个百分点，但理想化方案仍损失约5.21个百分点效用 | 隐藏身份联系会让部分跨会话任务更难 |
| 回答质量 ↔ 计算量 | BM25记忆提高5.56个百分点完全正确率，却多用约103万tokens | 小幅提升可能非常昂贵 |
| 遗忘安全 ↔ 模型调用 | 安全策略保持90%正确率，但只省11.46%调用 | 太保守就省不了多少钱；太激进又可能忘错 |
| 信息修复 ↔ 上下文长度 | 正确证据让答案更接近正确，同时大幅缩短输入 | 收益不只是“信息越多越好”，而是证据是否正确 |
| 记忆压缩 ↔ 全生命周期成本 | 固定长度重写在108个条件中同时更不准、更贵、更慢 | 不能只算查询 tokens，还要算反复整理记忆的维护成本 |
| 输出安全 ↔ 真实删除 | GateMem 最终答案 deletion leakage 为0/9，但相关内容在上下文中暴露9/9 | “没说出来”不能替代“没有存储或没有检索出来” |
| 结构利用 ↔ 标注可靠性 | 标注信号不可靠时，结构化方法可能选错策略 | 算法上限受输入标注质量限制 |

## 7. 现在最值得继续的研究方向

### 第一方向：只暴露任务真正需要的身份联系

问题：系统需要在不同会话间记住同一个用户，但稳定身份标签又会造成跟踪风险。

计划中的方法：

- 默认使用每会话变化的身份标签；
- 只有当前任务确实需要跨会话连续性时，才临时恢复联系；
- 恢复后立即撤销，不把稳定身份永久写进普通记忆。

最小实验：在两个公开跨会话 benchmark 上，与原始身份、固定标签、随机标签和永久不透明标签比较。

继续标准：关联风险明显下降，同时回答能力损失不超过预定范围；如果只能靠知道正确答案的理想化开关实现，就停止。

### 第二方向：先确认找到了对象，再执行遗忘

问题：当前遗忘控制器位于候选搜索之后。搜索不到内容时，再强的删除模型也无能为力。

计划中的方法：

- 同时使用关键词和多语言语义搜索；
- 为候选覆盖率单独估计风险；
- 候选为空或不确定时拒绝执行不可逆删除；
- 对多步修改逐步决定，而不是整段历史一次性处理。

继续标准：在新的公开测试集上修复 candidate-empty 失败，保持最坏语言安全，同时至少节省30%的真实模型调用。

### 第三方向：可验证的记忆错误修复

问题：给模型正确证据能让答案变好，但目前只有4个案例，而且没有产生严格正确答案。

计划中的方法：

- 先自动检测哪条记忆最可能导致错误；
- 只允许一次明确、可回滚的修改；
- 修改后重新回答；
- 用重复运行、等长度删除和无关替换排除偶然性。

继续标准：至少20–30个预先冻结的公开案例中，严格正确率也出现稳定提升，而不只是关键词重合分数提高。

### 暂时不作为主方法的方向

- “什么时候读取记忆”先作为评测问题，因为类似控制器已经很多；
- 结构标注方向先修测量器，不调用更多模型；
- 不继续扩大当前 BM25、Lethe router 或旧 annotation validator；
- 不把几个已有模块简单拼起来当作新贡献。
